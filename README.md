# vivo 广告计划助手（独立扩展 · V0.3.12 同名计划拦截与完成自动清理）

这个项目是**全新的 Chrome 扩展**，不依赖、不修改旧 LoveExtension。

## 当前已实现

- **批量创建**：一次设置 1～10 个广告计划，每张卡片始终展开并独立配置「广告计划名称、流量选择、素材类型、本地素材」；新增计划仍默认复制上一计划的名称，但点击「开始批量创建」时检查全部名称，若重复则在按钮旁提示冲突的计划编号和名称，定位到需修改的输入框并阻止开始；点「删除计划」直接删除，无浏览器原生弹框（最后一个计划不可删除）。
- **全部完成自动收尾**：最后一个计划确认提交并回到广告计划列表后，只刷新一次列表，自动清除本次任务和素材文件句柄，并关闭助手提示框；失败时保留错误提示，便于人工处理。
- **应用关联与推广名称可分别设为默认**：在各自的管理列表里点击「设为默认」，保存到当前浏览器；以后每次右键打开新建广告弹窗会自动预选这两项。当前默认项显示「✓ 默认」，再次点击可取消；删除默认项时会清除对应设置。应用默认精确绑定到某条行业/产品关联，即使多个关联属于同一应用也不会选错。
- 所有其他设置集中在底部**「公共参数设计」**，仍为标签与控件同行；「优化目标」和「出价金额」并排。安装定向为「不限 / 未安装 / 已安装」三个平铺单选，默认「已安装」；已修复单选按钮被输入框样式撑大的错乱。
- 创建前验证**全部计划**的名称、流量、素材格式/尺寸/数量，公共参数和监测链接；验证不通过时不启动自动创建。文件不会与其他计划混用，切换某个计划的素材类型只清除该计划的文件。
- **V0.3.8 图片/视频只保留文件句柄**：用户通过 Chrome 原生文件选择器授予访问权限，vivo 同源 IndexedDB 只保存 `FileSystemFileHandle` 和文件名、类型、大小、修改时间等元数据。跨标签页时按需调用 `handle.getFile()`，不再把基础素材的图片 Base64 或整个视频 `File` 存进数据库或扩展消息。校验和上传阶段才临时读取文件；唯一继续保存完整图片的是小尺寸默认头像。任务结束后删除句柄记录。
- 批量按列表顺序执行：**打开计划创建页 → 保存计划 → 新建广告 → 头像素材库优先（缺失时本地上传）→ 上传该计划的图片/视频 → 填写公共广告参数 →「提交并关闭」→ 返回原列表页继续下一计划**。中间计划不刷新列表，只有**全部成功后统一刷新一次**。一般定位/上传异常仍安全停止；保存/提交处的页面校验错误可暂停并人工修复，未完成前不创建下一计划。
- **V0.3.6 直接创建标签页**：第一条与后续计划都由扩展后台使用 `chrome.tabs.create()` 打开固定地址 `https://ad.vivo.com.cn/marketing/newads/add`，立即把任务绑定到返回的标签 ID。不再寻找或点击网页里的「新建广告」按钮，不使用鼠标模拟，也不要求或修改 Chrome 弹出式窗口权限。创建失败会安全停止当前任务，不重复提交已成功的计划。
- **V0.3.7 提交错误可人工修复继续**：点击「保存并新建广告」或「提交并关闭」后，检测到 vivo 表单错误（或未确认页面跳转）会保留当前页面、批次检查点和本地素材，在悬浮窗显示错误详情、「复制错误」「继续任务」「停止任务」。用户在当前页修改完成后点击「继续任务」，只对当前保存/提交动作进行一次重试；不会重新选择素材，也不会覆盖人工修正的广告字段。如果人工已保存并进入下一阶段，则跳过再次保存。若人工自行完成最终提交并真正跳到广告列表，后台照常按成功收尾，避免重复提交。刷新页面后暂停提示仍可恢复。若提交结果不明，重试前应先核实平台是否实际创建成功。
- **V0.3.5 悬浮提示与手动停止**：执行状态悬浮窗标题只写「vivo 广告计划助手」，右上角有 ×；底部始终有「停止任务」，仅发生错误时有「复制错误」。点击 × 或停止任务会向后台发出终止请求，取消当前批次以及转交到其他标签页的任务，清理未提交素材，不再显示已关闭的旧错误。已提交的广告不会撤销。
- **V0.3.5 重新右键从空白表单开始**：手动停止会清空旧计划名称、流量、素材、标题和监测链接，重置为 1 张空白计划卡；已保存的默认头像、应用关联、推广名称及其「设为默认」选择不删除。若升级前遗留了占用窗口的运行记录，再次创建会出现「结束旧任务」内联按钮，手动清理后保留本次新输入内容并重试。
- **V0.3.8 优化目标更短调试连接**：下拉框定位、遮挡检测、弹层展开及动画等待都在普通 DOM 中完成。仅针对“展开”和“选中”的各次原生鼠标事件短暂 `attach`，发送后立即 `detach`；Chrome 自身可能仍存在系统提示消失延迟。
- **V0.3.9 Debug 按需启用**：优化目标先尝试普通 DOM 点击并核验结果；普通点击成功时**完全不调用** `chrome.debugger`、不会因本扩展显示调试提示。只有页面不响应普通点击，才短暂启用原生点击；每次连接只发送鼠标按下/释放两个事件，立即断开，并在扩展后台控制台记录连接保持毫秒数。若非可信点击关闭了下拉菜单却未选中，会重新定位后再原生点击。
- **V0.3.10 提升带帮助图标的目标选项兼容性**：在当前可见弹层内按选项类名或 `role=option` 定位，优先读取独立文案，忽略帮助图标造成的尾部问号。保留网页禁用状态检查：选项若真正禁用则明确报错，不强行点击或改选目标。
- **V0.3.11 真实浏览器核对**：从用户当前 Chrome 中实际读取到 `<li class="el-select-dropdown__item" role="option"><div class="cvtype-text"><span class="cvtype-info">自定义拉活 <i class="icon-help">…</i></span></div></li>`，确认“自定义拉活”是普通 `li`，非禁用，且文本可以准确识别。进一步修复可能的异步菜单竞争：展开后不再只等待菜单出现任意一项并固定等 140ms，而是最多等待 6.5 秒直到**指定目标项本身唯一、可见、可点击**；失败时列出全部可见目标及禁用状态。
- **批量续建保留原列表页**：每条成功后激活原列表、关闭广告创建标签，再通过相同 `planStage` 流程开始下一条；切回时留出短暂过渡时间，所有计划都成功后才统一刷新列表。
- 报错提示与「开始批量创建」按钮在弹窗底部同一横行。
- 视频 16:9 和视频 9:16 已开放本地上传：视频与图片一样使用文件句柄，不落盘缓存视频内容；在实际上传页读取 `File` 后沿用尺寸入口、本地上传、已选数量和确认流程。
- 保留原来已成功的**单计划**完整工作流；只添加一个计划时也通过相同的批量状态机执行。
- 在 `https://ad.vivo.com.cn/marketing/newpromotion/plan` **直接右键页面空白处**，立即显示单页弹窗，不需要在浏览器右键菜单中再次选择。
- 仅接管计划列表页空白区域的右键。按钮、表单、链接、表格记录保持原生右键行为；按住 Shift 右键也可以使用浏览器原生菜单。
- 修复流量选择区被浏览器压缩、覆盖下面应用及安装定向等行的问题；表单超过窗口高度时内部滚动。
- 所有字段均为紧凑的「标签 + 输入框 / 选择框」横向排列。
- 流量分组和具体流量位可分别勾选，全部默认不选。
- 应用与行业/产品关联可新增、删除、选择；推广名称可新增、删除、选择。
- 管理的应用关联与推广名称保存在本浏览器 `chrome.storage.local`。
- 安装定向默认「已安装」；优化目标默认「自定义拉活」。
- 出价金额输入框默认填写 `0.1` 元/转化，可自行修改。
- 选择头像（256×256、JPG/JPEG/PNG、必须小于 50KB），选择单图或视频文件。
- 本地素材支持一次多选、再次追加，合计**最多 5 个**。相同文件不会重复添加，可通过文件名旁的 × 单独移除。切换单图/视频素材类型会清空之前选的素材。
- **头像文件会作为本浏览器扩展的默认头像保存在 `chrome.storage.local`**。同一 Chrome 个人资料下切换不同 vivo 账户仍可使用，点击「选择图片」可随时更换。不同 Chrome 个人资料和电脑之间不会自动同步。
- 实验性自动填写：从广告计划列表进入新建计划表单、设置选中的流量位、应用/行业产品、安装定向、优化目标、出价和计划名称。
- 点击扩展里的「开始创建广告」后，校验通过就自动填写并点击真实网页「保存并新建广告」，**不再显示浏览器确认弹窗或保存前二次确认**。

- 新标签页任务交接优先使用打开来源，网站隐藏打开来源时则利用相同浏览器窗口、近期唯一任务与完整页面 URL 进行匹配；页面加载前后都会尝试恢复任务。

- 根据新截图适配 `li.el-cascader-node` 应用与行业/产品菜单、`.el-select__wrapper` 优化目标下拉框、`label.el-radio-button` 安装定向选项。

- **唯一允许浏览器级鼠标模拟的位置是「优化目标」**：若尚未选中，先尝试普通点击；只有实际页面不响应时，临时使用 Chrome `debugger` 发送真实鼠标事件，并立即 `detach`。关闭连接遇到临时错误会主动重试，无法关闭时提示点击浏览器顶部「取消」。已选中或普通点击成功时不会启动模拟。

- **V0.2.22 复用旧版 LoveExtension V1.3.45 的四项基础检测**：在点击「开始创建广告」时才检查三条链接，不在输入时检查；全部留空则跳过并保留 vivo 默认值，只要填写一条就必须填写三条完整链接。
- 四项检测分别是：① 曝光/点击地址的外层 `partnerId` 必须删除干净、参数分隔符不能损坏（DeepLink 不检查 `partnerId`）；② 曝光/点击应为 `ugapi.alipay.com/monitor` 且 `action=expose/click`，DeepLink 应为 `alipays://platformapi/startapp`，并检查链接基本格式；③ `requestFrom`、嵌套的 `ugParams.media` 必须表示一致的 vivo 渠道；④ 三条链接必须有一致且唯一的 `ugParams.taskId`。

- 输入检查及界面反馈；多计划沿用从广告计划列表重新发起的方式，不依赖「提交并继续新建」的继承配置。

## 当前边界和注意事项

- **原单计划的头像、基础单图、广告标题及广告提交已有用户成功反馈。V0.3.6 首条及续建的标签页打开方式已改为 Chrome 扩展 API；新创建地址和第二条接力仍需 vivo 真实页面实测，视频上传也需实测。**
- **仅「优化目标」有可能使用 `debugger` 权限。** 普通点击有效时不会出现调试提示；需要原生鼠标时，连接只负责鼠标按下/释放，所有页面读取及等待均在连接外完成。Chrome 仍可能短暂显示「已开始调试此浏览器」；即使已断开，提示条的实际消失时间也由 Chrome 决定。请避免在该步骤同时打开 F12 开发者工具。
- **V0.2.9 新增 `webNavigation` 权限与 `adcc.vivo.com.cn/material-center-new` 的素材库子页面脚本。** 仅用来确定嵌入素材库的浏览器 frameId，并在这个子页面里勾选头像和确认，不访问其他网站的素材。
- 发行安装 ZIP 不包含 `tests`，测试文件只保留在开发目录中。
- 自动填写会在无法准确识别控件或无法确认控件状态时停止，并提示用户截图和提供对应 HTML，避免继续误操作。
- 点击「开始创建广告」之后，会在 vivo 后台尝试**真实创建广告计划**；不会再要求第二次确认。请使用测试计划，检查其开关保持关闭。
- **本版点击「开始创建广告」后将尝试真实提交广告**，不再在基础素材完成时暂停。扩展不会主动切换广告开关或点击「提交并继续新建」。请先用允许测试的计划核对账号、预算及投放状态。
- 落地页中「悟空建站」的具体地址没有配置入口，扩展保留 vivo 当前页面的默认选择。如果网站要求先指定悟空建站地址才能提交，扩展不会擅自选择；提交时会暂停，用户可在当前网页选好地址，再点击「继续任务」。
- 图片 16:9 支持 1280×720 至 1920×1080，9:16 支持 720×1280 至 1080×1920，长宽比需准确一致。视频预先核验其可读取的宽高比例，不额外猜测网站的视频大小或编码上限；实际格式/上传限制以 vivo 页面校验为准，失败则停止而不自动提交。
- 批量执行期间 **只临时保存图片/视频的文件句柄**，可由同源新标签页取得对应文件。任务成功、失败或取消准备时清理；再次启动新批次需重新选择文件。需要较新的 Chrome 和 HTTPS 环境，手动选文件后不要移动、覆盖文件或撤销读取权限。若 Chrome 在跨页面后撤销权限，任务会安全停止并提示重新选择，**不会回退缓存整个文件**。头像仍持久化在扩展本地。
- **新账户若素材库没有可匹配的头像，将尝试本地上传。** 只有服务端回显出素材被选入当前抽屉，且广告页头像预览加载成功，才继续至基础素材；如果上传后的列表结构有变化，会暂停并要求提供该处 HTML，不会假报成功。

## 安装

1. Chrome 打开 `chrome://extensions/`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择这个项目文件夹 `vivo-plan-extension`。
5. 打开 vivo 新版广告计划页并刷新一次。
6. 在**页面空白处直接右键**，即可弹出「批量新建广告」界面。

> 注：右键弹窗只在新版广告计划列表页生效，不会在浏览器地址栏、标签栏或其他 vivo 页面出现。

## 单计划完整提交流程测试

1. 在新版广告计划**列表页**空白处右键打开扩展，确认默认头像仍是保存过的 256×256 JPG/PNG 文件。
2. 选择「单图 16:9」和 1–5 张合规图片（也可以试「单图 9:16」）。
3. 填写 6–15 字符的广告标题。DeepLink、曝光监测地址和点击监测地址可以**三个都不填**；如果填，则必须三个一起填写并符合旧版支付宝 vivo 链接规则。广告名称自动沿用计划名称。
4. 点击「开始创建广告」。程序将**真实保存一个广告计划**，完成头像后点击匹配的尺寸标签，切换「本地上传」并上传单图。
5. 基础素材回显验证成功后，扩展会填写广告字段并只点击「提交并关闭」。若 vivo 校验通过并跳到广告列表，会激活并刷新原计划列表标签页、关闭刚才的创建标签页。
6. 检查广告列表中的新广告以及广告计划列表中对应计划；若仍停留在编辑页，查看页面是否要求选择悟空建站地址或其他必填项。

**注意：**本测试会在 vivo 后台真实创建广告计划、上传素材并尝试提交广告。可能在素材库新增图片。测试后务必检查计划和广告的状态。

**从旧版本升级：**把新版本的全部文件（包含 `material-frame.js`、`media-store.js`）覆盖到之前加载的同一个文件夹，然后在 `chrome://extensions/` 点击该扩展的「刷新」，并刷新 vivo 广告计划页。旧版尚未完成的批次必须停止并重新选择素材（旧版保存的完整文件不能转换成文件句柄），旧版临时媒体库会尽力自动清理。不要同时加载多个不同版本的文件夹。保留同一扩展安装身份也有助于保留本地的应用/推广名称与默认头像。

## 出错时如何辅助定位

本版已有标题、DeepLink、监测地址、广告名称和提交按钮的 DevTools 选择器。如果遇到新校验提示或「悟空建站地址」选项阻碍提交，请发来原始报错、当前页面截图及该控件的 `outerHTML`（不要包含 Cookie、Token 或个人隐私），以便进一步适配。
